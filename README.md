# Лабораторна робота №5. Алгоритми на стеку та черзі

## Завдання 1. Перевірка дужок

Для `a = 2` дужки всередині подвійних лапок ігноруються. Індекс помилки рахується від 0.

| Вхід | Результат | Індекс помилки |
|---|---|---:|
| `(a[b]{c})` | Збалансований | -1 |
| `([)]` | Незбалансований | 2 |
| `)(` | Незбалансований | 0 |
| `((` | Незбалансований | 0 |
| Порожній рядок | Збалансований | -1 |
| `("[")` | Збалансований | -1 |
| `(` | Незбалансований | 0 |

Рядок `(` містить рівно `K = 1` відкривальну й `K - 1 = 0` закривальних дужок.

## Завдання 2. Зворотний польський запис

| Вираз | Результат |
|---|---|
| `3 4 + 2 *` | 14 |
| `5 3 -` | 2 |
| `8 2 /` | 4 |
| `2 3 4 * +` | 14 |
| `2 3 ^` | 8 |
| `5 0 /` | Помилка ділення на нуль |
| `5 2 %` | Помилка невідомого токена |
| `+` | Недостатньо операндів |
| `5` | 5 |
| `2 3` | Забагато операндів |
| Порожній вираз | Помилка порожнього виразу |

Власний вираз із результатом `K = 1`: `2 3 + 4 * 5 - 15 /` → `1`.

## Завдання 4. Власний стек

Початкова місткість масиву — `K % 4 + 2 = 3`. Після `K % 4 + 3 = 4` викликів `Push` місткість подвоїлася до 6.

| Виклик | Count | Capacity |
|---:|---:|---:|
| Push 1 | 1 | 3 |
| Push 2 | 2 | 3 |
| Push 3 | 3 | 3 |
| Push 4 | 4 | 6 |

Перевірки дужок на власному стеку дали ті самі результати, що й на стандартному `Stack<char>`.

## Завдання 5. Обґрунтування вибору структур даних

**Завдання 1 — стек.** Вкладені дужки перевіряються за принципом LIFO: остання відкрита має закритися першою; стек безпосередньо забезпечує такий порядок, тоді як список дозволяє довільно звертатися до елементів і сам його не обмежує. Черга обробляла б відкривальні дужки в порядку надходження, тож вкладені пари могли б зіставлятися неправильно.

**Завдання 2 — стек.** Для операції беруться два останні операнди, а стек забезпечує потрібний LIFO-порядок; список не обмежує доступ лише до цих верхніх значень. Черга діставала б найстаріші операнди, через що, зокрема, віднімання та ділення могли б дати неправильний результат.

**Завдання 3 — черга.** Заявки обслуговуються в порядку надходження, а незавершена заявка повертається в кінець; черга відповідає цьому порядку FIFO. Стек обробляв би останню заявку першою, а список із `RemoveAt(0)` довелося б зсувати після видалення першого елемента.

У ЛР №4 додавання 100 000 елементів через `Add(x)` зайняло 2,37 мс, а 100 000 вставок через `Insert(0, x)` — 1024,97 мс. Це демонструє вартість зсуву елементів під час зміни списку на початку.

Окремий прямий замір для 10 000 елементів, середнє за 5 повторів:

| Операція | Час |
|---|---:|
| `Queue.Dequeue()` | 0,0314 мс |
| `List.RemoveAt(0)` | 8,8458 мс |

У цьому замірі `List.RemoveAt(0)` був приблизно у 281,71 раза повільнішим: він зсуває решту елементів, тоді як `Queue.Dequeue()` не потребує такого зсуву.
